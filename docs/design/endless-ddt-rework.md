# Endless DDT 改造计划（讨论稿）

> 状态：**讨论稿，未实施**。本文只定方向与旋钮草案，落码前逐条拍板。
> 现行真值见 [combat.md](./combat.md) 与 `src/level-config.ts`。
> 背景：精英（elite）机制已废弃移除，特殊波只剩 6 波一 boss；DDT 的
> 预算构成随波次线性增长但受 `maxUnitsPerWave = 8` 封顶，wave 6–10 后
> 难度曲线进入平台，且金币在 wave 4–5 后失去消耗出口（资本上限 1000g）。

## 设计原则

1. **DDT 是动态、无感的**：调节不以"惩罚"的面目出现，玩家只感到局势
   越来越紧，说不出哪一刀是系统砍的。
2. **收入是第一个要治理的**：敌方成长先放温和，紧张感的真正来源是
   "金币不再无限涨"——收入要有标准、有波动、随波次越来越苛刻。
3. **难度系数化，不魔改单位**：一切成长走全局系数与构成，伤害矩阵、
   单位属性表保持单一真值。
4. **每个杠杆一个旋钮，落在 `ENDLESS`**，改码必改表（combat.md）。

## P0 收入体系（收入标准 + 波动 + 紧缩）

现状问题：赏金统一 200，与预算成本（1 / 0.9 / 0.6）脱钩——扑翼机
"威胁/成本"与"赏金/成本"双高，预算盘与收入盘都被扭曲；5 槽 × 200g
资本上限让 wave 4–5 后金币成为无意义数字。

### P0-1 赏金分档（收入标准）

赏金随预算成本定价，收入与威胁对齐：

| 单位 | 预算成本 | 赏金草案 |
|---|---|---|
| pirate-ship | 1.0 | 200 |
| bombardier | 0.9 | 180 |
| ornithopter | 0.6 | 120 |

实现：`REWARD_TABLE` 已按档位付费，只需把 `RewardTier.Stock` 细分为
按 `unitType` 查 `ENDLESS.bounty` 表（一个新旋钮块），ShellHitSystem
击杀点零分支。

### P0-2 清波速度赏金（正向波动，非 RNG）

一波全部击杀且用时 ≤ `clearBonusWindowSec`（草案 45s，待实测标定）→
本波赏金 × `clearBonusRatio`（草案 1.25）。波动挂在技巧上而不是随机
数上：玩家可感知、可争取、可规划。director 已掌握清波时刻，实现为
击杀点读取一个波内累计系数，零新资产。

明确不做：纯随机 ±roll 爆金币——玩家无法对坏波动做决策，只有挫败。

### P0-3 收入紧缩（爆金币越来越苛刻）

三层叠加，净收入随波次自然缩水：

1. **赏金折价**：`bountyDecayPerBoss`（草案每次 boss 出场后全档赏金
   ×0.95）——用 boss 里程碑做刻度，可预测、可预告。
2. **建造涨价**（见 P3，可选，若启用则 1 可放宽）。
3. **boss 赏金不随波次上涨**（固定 800×5 套餐）——相对购买力自然贬值。

目标态：钱从"无意义数字"变成"在流血的资源"，run 的终局是破产——
修不起、换不起、墙被磨穿。危机感由数学产生，不靠剧本。

## P1 敌方温和棘轮（动态百分比，无感）

预算构成到顶后（wave ~6–10），难度继续由系数承载：

- `hostilityScale`：敌方矩阵伤害全局系数，**每 `hostilityStepWave`（4）
  波 ×`hostilityStepRatio`（草案 1.05，即 +5%）**。温和线性和——
  wave 20 ≈ 1.3×，wave 40 ≈ 1.65×；好玩家终局 wave 30–40，
  一般玩家 15–20，具体等收入体系落地后实测标定。
- **豁免**：boss 特攻（激光 60%、死光 75%/50%）不乘系数——它们已是
  大额固定百分比，避免双倍计息。
- **只涨不跌**（棘轮）：保证 run 必然有终点；压力/存款橡皮筋继续
  负责短期起伏，不负责长期方向。
- 实现点：`shell-hit-system.ts` 矩阵查询后的乘法点（原精英 ×4 的
  位置），一个 director 级标量，命中时读一次，零分配。
- 明确不做：敌方攻速/血量缩放（无必要不引入第二把刀）。

## P2 老兵单位（DDT 混编的新敌种）

替代已移除的"精英轮"：不再是独立特殊轮，而是**编队内混编的等级变体**。

- 形态：wave 条目 `veteran:pirate-ship` 前缀，与原 elite: 前缀同机制
  位置；外观同款模型，靠可辨识但不喧宾的标记区分（草案： hull tint
  或 ×1.15 尺寸，开放讨论）。
- 属性：走 `veteranDamageRatio` / `veteranBiteRatio` 等等级系数，不再
  用"固定咬伤"特例——与 P1 的系数化思路一致。
- 混编规则：`veteranStartWave`（草案：第 2 个 boss 之后）起，预算购买
  时以 `veteranChance` 概率把一个 stock 单位升级为 veteran，升级差价
  从预算扣除（船 1.0 → veteran 1.4 之类）。
- 与旧精英的边界：数量受预算与 `maxUnitsPerWave` 约束，不再是"一整波
  只来一个大家伙"；赏金走 `bounty` 表 veteran 档。

## P3 建造涨价（可选，与 P0-3 二选一或并用）

`ECONOMY.unitValues` 保持书面真值，建造/换购实付 =
`value × buildInflation(wave)`（草案：每次 boss 出场后 +10%，即
`× 1.1^bossCount`）。只涨建造、不动修理——修理涨价会精确惩罚正在输
的玩家（死亡螺旋），抵消 `pressureMin` 橡皮筋；建造是贪婪性支出，
涨价无道德风险。
